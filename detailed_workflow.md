## 2. Technical Sequence: AI Tutor Chat with SSE Streaming

This sequence diagram illustrates the lifecycle of a real-time conversational exchange with the LearnGenie AI tutor, utilizing **Server-Sent Events (SSE)** for latency-free streaming.

```mermaid
sequenceDiagram
    autonumber
    actor Student as Student / Client
    participant App as React UI (/chat/:id)
    participant Server as Express Server
    participant DB as PostgreSQL (Drizzle)
    participant Gemini as Google Gemini API
    
    Student->>App: Type question & click Send
    App->>App: Render student message instantly in UI chat list
    App->>Server: POST /api/chat/conversations/:id/messages (content: text)
    
    activate Server
    Server->>DB: Query conversation details & full history (conversationsTable, messagesTable)
    DB-->>Server: Return ordered array of message history
    
    Server->>Server: Format messages: Prepend SYSTEM_PROMPT & map history roles
    Server->>Server: Set HTTP Headers (Content-Type: text/event-stream, Cache-Control: no-cache)
    Server-->>App: Establishes SSE stream connection (HTTP 200 OK)
    
    Server->>Gemini: Invoke generateContentStream(gemini-2.5-flash, contents)
    
    loop Stream Chunks
        Gemini-->>Server: Stream text chunk
        Server-->>App: Send SSE payload: data: {"content": "chunk_text"}
        App->>App: Append chunk to AI bubble token-by-token
    end
    
    Server->>DB: Save User message to messagesTable
    Server->>DB: Save combined AI Assistant response to messagesTable
    Server->>DB: Insert event to activityLogTable (type: "ai_chat")
    
    Server-->>App: Send SSE completion payload: data: {"done": true}
    deactivate Server
    
    App->>App: Stop stream listeners & finalize message state
    App-->>Student: Finished typing, user can ask next question
```

## 3. Server-Client Boundary: Study Plan Generation Workflow

This diagram outlines how a personalized study plan is requested, generated by AI in a strict structured format, persisted in the database, and rendered to the client.

```mermaid
sequenceDiagram
    autonumber
    actor Student as Student / Client
    participant App as React UI (/planner)
    participant Server as Express Server
    participant Gemini as Google Gemini API
    participant DB as PostgreSQL (Drizzle)
    
    Student->>App: Enter subject, target exam, daily study hours, deadline, & skill level
    App->>App: Validate form inputs locally
    App->>Server: POST /api/study-plans (JSON body)
    
    activate Server
    Server->>Server: Validate request body against CreateStudyPlanBody (Zod Schema)
    Note over Server: Server constructs prompt instructing Gemini to return a strict JSON schema
    
    Server->>Gemini: POST generateContent(gemini-2.5-flash, prompt)
    Gemini-->>Server: Return structured text (JSON matching requested schema)
    
    alt Parsing Success
        Server->>Server: Strip markdown formatting & parse JSON string
    else Parsing Failure / Timeout
        Server->>Server: Fall back to default structured study plan schema
    end
    
    Server->>DB: Insert study plan details & planContent to studyPlansTable
    Server->>DB: Insert event to activityLogTable (type: "study_plan")
    DB-->>Server: Return inserted record (with plan ID)
    
    Server-->>App: HTTP 201 Created (JSON Response of Study Plan)
    deactivate Server
    
    App->>App: Trigger confetti animation & cache study plan
    App-->>Student: Display interactive schedule (Daily schedules, Milestones, and Tips)
```

## 4. Technical Sequence: AI Quiz Generation & Performance Review

This sequence illustrates the process of generating custom quizzes, capturing student answers, and persisting quiz performance scores.

```mermaid
sequenceDiagram
    autonumber
    actor Student as Student / Client
    participant App as React UI (/quizzes/:id)
    participant Server as Express Server
    participant Gemini as Google Gemini API
    participant DB as PostgreSQL (Drizzle)
    
    Student->>App: Click "Generate Quiz" on subject & set parameters (difficulty, question type)
    App->>Server: POST /api/quizzes (JSON body)
    
    activate Server
    Server->>Server: Validate body against CreateQuizBody (Zod Schema)
    Note over Server: Server instructs Gemini to return a array of question objects (options, correctAnswer, explanation)
    
    Server->>Gemini: POST generateContent(gemini-2.5-flash, prompt)
    Gemini-->>Server: Return structured JSON of questions
    
    Server->>DB: Save quiz topics & question array to quizzesTable
    DB-->>Server: Return inserted quiz record
    Server-->>App: HTTP 201 Created (quiz data)
    deactivate Server
    
    App->>App: Render quiz timer & first question
    Student->>App: Answer all questions & submit quiz
    App->>App: Calculate score & compare answers with correctAnswer
    App->>Server: PATCH /api/quizzes/:id/score (body: {score})
    
    activate Server
    Server->>DB: Update last_score in quizzesTable for the given ID
    Server->>DB: Log quiz activity (activityLogTable)
    DB-->>Server: Success
    Server-->>App: HTTP 200 OK
    deactivate Server
    
    App->>App: Play Confetti (if passed) & show answer explanations
```
